# 새 Core 파일 만들기 (유형 C · "복제해서 깎기") — use_figma 4~6회

2026-09-18 Ken 결정. 새 Core는 **프로젝트 파일의 복제본**을 깎아서 만든다. 파일 경계를 코드로 넘지 않는다(지침서 §0-8): 복제본 안에는 원본 페이지가 다 들어 있으므로 화면은 **같은 파일 안 `clone()`** 으로 옮기고, 마스터를 다 만든 뒤 작업 페이지를 지운다. 규격·수치는 지침서 §6-2, 수록은 §4-1(오버뷰). 묶음마다 `get_screenshot`을 남긴다.

## 0. 사람 손 (요청 전, 1분)

프로젝트 파일 우클릭 → **Duplicate** → 이름 `[Core] <프로젝트 커버 Page Name>` → Core 폴더로 이동 → 요청함/Notion 행의 **Core 파일 링크** 칸에 붙여 넣기. 원본 프로젝트 문서는 그대로 둔다(기준 문서 역할, 링크 카드가 가리킴). 복제본이 없으면 도우미는 `확인 필요`로 멈춘다(파일 복제는 API에 없다).

## 2. 두 원칙 + 하나 (지침서 §0-6·§0-7·§0-8)

- **복붙**: 화면은 `clone()`으로 그대로. 도우미가 만드는 것은 섹션·설명 바·링크 카드·입구 텍스트뿐. 복제마다 B' 대조 → 차이 0.
- **빠뜨리지 않기**: 시작 전에 문서의 섹션 목록으로 수록 대조표를 만들고, 끝난 뒤 모든 행이 마스터에 있거나 "미수록 이유"가 적혀 있는지 센다.
- **파일 경계를 코드로 넘지 않는다**: 다른 파일의 화면이 필요하면 사람 붙여넣기 1회(요청 링크로 알린다) 또는 하이퍼링크. 다시 그리기(깊은 복제)는 쓰지 않는다 — 홈 1장에 코드 150KB를 태우고도 오버라이드가 어긋난다(2026-09-18).

## 3. 주의 (겪은 것)

- `importComponentByKeyAsync`는 파일에 라이브러리가 연결돼 있어야 한다. 스크린 설명 컴포넌트·상태 뱃지는 됐고, `영역 설명 컴포넌트`(진입 마커)는 라이브러리에서 더는 못 불러온다 → 단순 프레임(◀ + 텍스트).
- 새로 만든 인스턴스의 하위 노드는 **같은 호출 안에서 `getNodeByIdAsync`로 바로 안 잡힐 때가 있다** — 다음 호출에서 잡힌다. 오버라이드 손질은 만든 다음 호출에서.
- Figma 연결이 끊기면 도구 접두어가 바뀐다(`mcp__Figma__use_figma`). ToolSearch로 다시 찾고 노드 ID로 이어서.
- 복제본에서 로컬 컴포넌트 페이지를 지우기 전에 마스터의 인스턴스를 분리한다(위 F). 스텝메이드는 헤더 컴포넌트 9종·인스턴스 32개가 로컬이었고, 분리 후 두 페이지 삭제(2026-09-18).
- `saveVersionHistoryAsync`는 이 연결에서 거부된다 → Named version은 사람이 저장하거나, 복제본이므로 실패 시 파일을 지우고 다시 복제한다.
- 🔵 바의 설명 부품(`설명1`)은 기본으로 `Show Title`이 켜져 "Title" 글자가 남는다 → `setProperties({'Show Title#…': false})`. 그러면 바 높이 158→122, 화면은 y 436.
- 복제 직후 스크린샷에서 큰 헤더 이미지(4096px)가 그 아래 단색으로 렌더될 수 있다(해시·바이트는 있음) — 에디터 확인으로 넘긴다(2026-09-18).
