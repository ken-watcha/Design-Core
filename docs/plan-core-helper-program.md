# Core 도우미 프로그램 설계안 (2026-10-02, 플러그인 대체)

> Ken(2026-10-02): "해봤을 때 플러그인은 아닌 것 같다, 프로그램으로 만들어 보자." → 이어서 **"데스크톱 앱, 팀 내부용이라 로그인은 없어도 된다"**. 아래 §0이 현재 방향, §1~ 은 처음 추천했던 웹 페이지안(엔진 설계는 공통).

## 0. 데스크톱 앱 (Ken 선택, 2026-10-02)

- 앱 자체 로그인 없음. 팀 공용 설정(Figma 읽기 토큰 등)을 앱에 넣어 배포. 맥 서명 없이 사내 배포(처음 열 때 우클릭 → 열기).
- **Figma 쓰기가 관건**: 쓰기는 플러그인 API로만 되고, 밖에서 부르는 길은 Figma MCP(`use_figma`)뿐. Figma MCP는 허가된 클라이언트만 받는다 — 우리 앱 이름으로 동적 등록(`POST api.figma.com/v1/oauth/mcp/register`)을 시험했더니 Figma가 403(2026-10-02, 프록시가 아니라 Figma CloudFront 응답).
- 쓰기 방법 후보(Ken 선택 대기): ① 앱 안에 Claude 엔진(Agent SDK) — Claude가 허가된 Figma 클라이언트, 팀 키 1개 내장, 실행마다 사용량 ② 읽기는 앱(REST 공용 토큰) + 쓰기만 작은 플러그인 ③ 각 노트북의 Figma 데스크톱 앱 로컬 연결로 쓰기가 되는지 조사(미확인).
- 판단(분석·판별·수록 대조표)은 플러그인 코드(`plugin/code.js`)를 옮겨 규칙으로 — 이건 어느 쓰기 방법이든 공통.

## 1. 형태 — 웹 페이지 하나 (요청함을 실행기로 키운다)

- 디자이너는 링크 하나를 연다 → 프로젝트 Figma 링크를 붙여넣는다 → **분석** → 판별·수록 대조표 확인 → **실행**.
- 설치 없음. 각자의 claude.ai 계정 + 각자의 Figma 연결로 돈다(첫 사용 때 허용 1회).
- 실행 중 Claude를 부르지 않는다. 판단은 규칙(`plugin/rules.json` → 이름만 옮김)과 Core 색인(`core-index/core-index.json`)으로.
- 기록(요청·로그·학습 가설)은 페이지의 공유 저장소(db)에. Ken 검토 화면도 같은 페이지 안, Ken에게만 보이게.

## 2. 왜 이 형태가 되나 (확인된 사실)

| 사실 | 근거 |
|---|---|
| 페이지가 뷰어의 Figma 연결로 `use_figma`(플러그인 API 코드)를 실행할 수 있다 | 요청함(6aabb40e…)이 Cover 읽기에 이미 사용 |
| `use_figma`는 파일이 열려 있지 않아도 되고 **어느 파일이든** 키로 연다 | 세션 2·5 |
| 플러그인의 분석·새 Core 만들기 코드는 순수 플러그인 API라 그대로 옮겨진다 | `plugin/code.js` `analyze()`·`buildNewCore()` |
| 파일 사이 복붙은 어떤 형태로도 불가 | 세션 5·9/18 |

플러그인과 달리 **파일을 열 필요가 없고, 여러 파일(프로젝트 파일·Core 15개)을 한 화면에서 오갈 수 있다.**

## 3. 플러그인에서 옮길 때 바뀌는 것

| 플러그인 | 프로그램 |
|---|---|
| clientStorage (계획·기억) | 페이지 db (`plans`·`memory`·`hypotheses`) — 노트북이 아니라 팀 공용 |
| 열린 파일 1개 | 링크로 아무 파일 |
| 사람이 선택 → ⌘C (기존 Core 갱신) | 프로그램이 "복사할 화면 목록 + 해당 노드로 가는 링크"를 보여 줌. 붙여넣기는 여전히 사람 1회 |
| figma.notify / selection | 페이지 안 진행 표시 |
| 호출 1회 무제한 | `use_figma` 코드 50KB·호출당 페이지 전환 1회 → 단계별로 나눠 호출 |

## 4. 첫 버전 범위

1. 링크 → Cover 읽기 → 파일 종류·크기별 후보·수록 대조표·판별 후보 표시 (읽기만)
2. 새 Core: "Duplicate 하세요" 안내 → 복제본 링크 붙여넣기 → 마스터 만들기·대조·작업 페이지 정리 (쓰기)
3. 기록·학습 가설 저장, Ken 검토 화면

기존 Core 갱신(A/B)은 2단계 — 로그인/온보딩 검증이 끝난 뒤.

## 5. 대안 (Ken 선택지)

- 데스크톱 앱: 같은 엔진, 껍데기·로그인·배포를 우리가 만들어야 함(몇 주).
- Claude Code 앱: 만들 것 거의 없음, 화면은 채팅.
