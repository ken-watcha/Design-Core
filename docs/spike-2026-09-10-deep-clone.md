# 스파이크 — 파일 간 "깊은 복제" 가능성 (2026-09-10)

> 목적: 설계안 v2의 핵심 난제 "프로젝트 파일의 화면을 Core 파일로 옮기기"가 Figma 연결(`use_figma`)만으로 되는지 잰다. Figma API에는 파일 간 복사가 없으므로, 화면의 속성을 읽어 다른 파일에 **다시 그리는** 방식을 시험했다.
> 대상: [Core] 소식함 마스터의 화면 1장 `3:642`(375×812, 인스턴스 9개) → 스텝메이드 고도화 파일의 **브랜치 "Claude Test"**(`XIolz3S5ClSf5VEaBkwDi6`) 🔁 Core 반영사항 페이지에 재구성. 본 파일에는 쓰지 않았다. 결과 프레임: https://www.figma.com/design/XIolz3S5ClSf5VEaBkwDi6/?node-id=3410-6

## 확인된 한계 2개

1. **이미지 해시는 파일 경계를 넘지 못한다.** 왓챠파티 Core의 이미지 해시 3개를 브랜치에서 `getImageByHash`로 찾으면 전부 null. 이미지를 옮기려면 바이트를 옮겨야 하는데, `use_figma` 실행 환경엔 `fetch`가 없고 코드 길이 한도(50,000자)가 있어 **약 30KB 이하 이미지만** base64로 통과한다. 포스터급(200~700KB)은 불가.
2. **인스턴스 교체 속성이 로컬 컴포넌트를 가리키면** (하단바 활성 탭의 `Instance#…: "9:1043"`) 대상 파일엔 그 ID가 없어 기본값으로 남는다.

## 그래서 "화면 옮기기"의 최종 방법

| 화면 종류 | 방법 | 자동화 |
|---|---|---|
| 라이브러리 인스턴스 + 텍스트로 된 화면 (왓챠 화면 대부분) | 깊은 복제 | 자동 |
| 작은 이미지(아이콘·로고, ≤30KB)가 있는 화면 | 깊은 복제 + 이미지 base64 전송 | 자동 |
| 큰 이미지(포스터·배너)가 있는 화면 | 깊은 복제 후 **이미지 자리는 대상 파일에 이미 있는 같은 해시 → 없으면 회색 자리표시 + 이름에 "(이미지 미전송)"**, 요청 표에 "포스터 n장 붙여넣기 필요"로 보고 | 반자동 (이미지만 사람) |
| 새 Core (프로젝트 파일이 Core가 되는 경우) | 같은 파일 안 복제 → 옮길 것 없음 | 자동 |

Core 마스터의 포스터는 더미 데이터라, 자리표시로 두고 담당자가 원하면 채우는 정책도 가능 (Ken 결정).
