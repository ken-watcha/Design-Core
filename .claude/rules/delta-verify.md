# Δ 표 검증 규칙 (기존 Core 갱신)

2026-10-12 스텝메이드 WEB 768 오판에서 나온 규칙. 경위는 `.claude/lessons_log.md` 같은 날짜 항목.

- **교체·추가·"문서에 없음"은 사람에게 말하기 전에 직접 대조한다.** 앱(또는 내가) 낸 Δ 표에서 유지가 아닌 칸이 있으면, 그 Core 화면과 같은 폭의 프레임을 프로젝트 문서 **전체 페이지**에서 찾아 글자·이미지·크기를 비교한다(REST `GET /v1/files/:key/nodes` 로 읽기만). 같은 화면이 있으면 "유지"로 고쳐서 보고한다.
- **이름으로 거르지 않는다.** "Guide"·"가이드"·"예시" 같은 이름의 프레임도 Core 화면의 원본일 수 있다. 대표 후보 점수(`rules.json` `screenPick.avoidNames`)는 새 Core를 고를 때만 쓰고, 기존 Core와 대조할 때는 모든 같은 폭 프레임을 본다.
- **"거의 같음"은 같음이다.** 크기·글자·이미지가 같고 요소 몇 개(가이드 표시 사각형 등)만 다르면 Core로 옮길 때 사람이 정리한 흔적이다. 유지로 보고, 표에 "거의 같음(요소 N개 차이)"이라고 이유를 적는다. 앱 기준은 `app/engine/delta.js`의 `sigMatch`(요소 수 3개 이내).
- **시험에 결과를 박을 때는 Figma에서 눈으로 확인한 값만 쓴다.** 엔진이 낸 숫자를 그대로 기대값으로 넣으면 오판이 시험 통과로 굳는다.
- 대체 화면을 권하는 건 위 대조를 마친 뒤에만 한다.
